# Map Director v1

This synthetic adaptation follows HCRC's private discrepant-map route communication paradigm, not its original corpus or imagery. One episode is an iterated same-dyad session: exactly two banked rounds with persistent agent-side message/image history. The giver and follower objects are created once and never reset. The default session contains missing/renamed landmarks then a duplicate landmark; a second session pairs a displaced landmark with a matched control. The complete two-round task schedule is one bank row and one statistical episode.

Both seats receive actual private PNG maps. The giver sees a red target polyline; the follower sees its own map and, after editing, its purple draft. Maps are north-up but use independently scaled/offset coordinate frames. Observations never contain partner images, canonical landmark records, world coordinates, target routes, bank IDs, tolerances or answer keys. Visible axis numbers and landmark names are intended stimuli. Communication is text. The giver cannot inspect follower drawings, submissions or validity feedback.

Each round alternates one giver instruction and one follower reply. Follower JSON actions may replace its entire polyline with 2–128 finite local [x,y] points inside its own displayed axes, and may submit. Invalid drawing syntax preserves the last valid draft and provides private formatting feedback; no geometric correctness feedback is provided until the round closes. Empty submissions cannot end a round. The configurable max_turns bounds giver/follower exchanges, default six. Budget exhaustion scores the latest drawing as unsubmitted and unsuccessful. New-round setup clears drawings and submissions, but retains seat history. No provider/runtime failure substitutes a scripted agent or counts as successful play.

Landmarks are reference points rather than obstacles. The fixed physical target route is unchanged if a follower landmark is missing, duplicated or displaced. Shared anchors and relational instructions keep each example solvable. Grids exist for precise route entry; copying giver numbers cannot solve the follower's different frame. Cross-map coordinate conventions may legitimately be negotiated.

The ordered-frechet-v1 oracle maps follower local coordinates into the evaluator's world frame. It resamples both polylines at at most one world unit per sample, computes discrete Fréchet distance (preserving traversal order), endpoint maximum error, and submitted/target path-length ratio. Success requires explicit submission, Fréchet ≤3 world units, endpoints ≤2, and length ratio ≤1.15. These tolerances are immutable bank data. Per-round outcomes report success, route_error, endpoint_error, length_ratio and turns_used; episode success_rate is their mean. No threshold adjustment or oracle-informed fallback is used for live tests.

Public message events carry speaker/text/round. Observation events carry speaker/round/content/visibility=private with opaque asset digests. Each drawing event records the follower's exact committed route as a private image and an action/validation summary. Round_end records the same final drawing, submission status, and scored outcome with speaker=follower and visibility=private, so replay shows first-turn submissions as well as revisions and budget exhaustion. Round_end and final trace are evaluator evidence. Trace config pins the composite image-bank hash and all used image digests. Static images are banked; runtime draft overlays are content-addressed in config.asset_root and all enter final config.image_assets. These owner-visible trace artifacts are never automatically added to another seat's observation.

The root executable LangGraph is next_round → round child → score_round → next_round → finalize. The real child is begin_round → giver AgentStep → publish_instruction → follower AgentStep → record_drawing, looping only when unsubmitted with budget remaining. There is no descriptive workflow catalog or hidden agent call.

The shared runner owns opening/closing the attempt session; setup emits game_start before session.started, then play starts only after registration. Remote seats use staged /2 submit_action with deadline-scoped capability claims; action acknowledgment alone is not completion. Model execution, JSON parsing and accumulated conversation stay agent-side; validation, route commits, permissions, oracle and trace evidence stay environment-side.

Sources: https://groups.inf.ed.ac.uk/maptask/maptask-description.html


# Map Director v2: independent jitter and route families

V2 is a separate scientific release (`map_director@v2`, `map_director_tiny_v2.yaml`) with a separate `maps_v2.jsonl` bank and `ordered-gates-corridor-v2` oracle. The installed catalogue advertises V2 for new designs. Existing V1 release files, bank hashes, oracle, and legacy bare configurations remain V1; use `task_version: v2` for direct V2 construction. A V2 bank digest cannot be used in V1 or vice versa. Frozen V1 experiments continue to use their pinned runtime and inputs.

The four pilot sessions cross jitter radii 4 and 8 map units with noise seeds 17 and 41. Each contains two rounds with the same dyad and accumulated seat history. Every landmark, including START and FINISH, receives an independent draw uniform in a disc for each seat and round. Seeds, draws, radii, realized positions, and images are frozen in the bank and covered by its composite digest. Noise is sampled when authoring the bank, not resampled between turns or silently from wall-clock randomness. The renderer retains independent local axis scales/offsets. Corresponding landmark positions do not admit any exact affine map: authoring verifies the unique affine alignment fixed by three noncollinear shared anchors disagrees with other anchors. A single linear transform therefore cannot exactly transfer all references.

The intended route is relational. Directional arrows disambiguate traversal when the route doubles back or crosses itself. The giver's red line starts at its START cabin, passes between three ordered pairs of named landmarks, and ends at its FINISH chapel. The evaluator constructs the follower reference from those same relations on the follower's independently jittered map. V2 does not compare the drawing with a globally transformed giver polyline. Round two changes the passage order as well as the landmark positions. All landmarks are present and uniquely named in these pilot items; noise is the manipulated discrepancy.

Each passage is the middle half of the segment between its two landmarks, expanded by 1.5 units perpendicular to that segment. The accepted path must enter these finite gate regions in order. Gate intersections use continuous polyline segments, so adding vertices or varying sampling density does not manufacture or remove crossings. Gate membership is evaluated along the traversal, permitting earlier incidental crossings when a later requested passage is reached again. Paths may turn anywhere within a gate; they need not hit a landmark, a midpoint, or an exact gate line. Landmarks are reference points, not obstacles.

Success also requires explicit submission, maximum endpoint error ≤3 units, ordered discrete Fréchet error ≤8 units relative to the follower reference (sample spacing ≤1 unit), and submitted/reference length ratio ≤1.6. The corridor and length bound prevent large detours or shortcuts from becoming valid solely by touching gates. Multiple distinct polylines through the same ordered passages can succeed; there is no single answer vertex list. Excess-length paths fail before distance computation and report an uncomputed (`null`) route_error. The geometric oracle, realized shifts, correspondence records, gate regions, follower reference, tolerances, and seeds are evaluator-only information. Seats receive only their own PNG, public dialogue, public version rules, and private syntax feedback.

V2 uses the same compact executable graph, actual local or `/2` remote model seats, image transport, final drawing replay, and runner-owned lifecycle as V1. Registration carries the public task version so local and remote strategies use identical rules. Outcome evidence adds gates_passed, gate_count, gate_order_ok, and the V2 oracle version; no new correctness feedback reaches the giver during play.

Scripted V2 smoke policies read only their own raster markers and public instructions. They know this pilot bank's named landmark bands and axis formats, and are explicitly deterministic fixtures, not evidence of general visual grounding. Model-backed seats receive none of that fixture's layout code or evaluator geometry.

Run the two-round fixture with `a2a-run games/map-director/experiments/v2_example.yaml --smoke-test`. Author additional frozen stimuli with `python games/map-director/scripts/build_bank_v2.py` after extending its explicit seed/radius list; this updates both bank and portable release input pins.
