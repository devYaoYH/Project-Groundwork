# Map Director v1

This synthetic adaptation follows HCRC's private discrepant-map route communication paradigm, not its original corpus or imagery. One episode is an iterated same-dyad session: exactly two banked rounds with persistent agent-side message/image history. The giver and follower objects are created once and never reset. The default session contains missing/renamed landmarks then a duplicate landmark; a second session pairs a displaced landmark with a matched control. The complete two-round task schedule is one bank row and one statistical episode.

Both seats receive actual private PNG maps. The giver sees a red target polyline; the follower sees its own map and, after editing, its purple draft. Maps are north-up but use independently scaled/offset coordinate frames. Observations never contain partner images, canonical landmark records, world coordinates, target routes, bank IDs, tolerances or answer keys. Visible axis numbers and landmark names are intended stimuli. Communication is text. The giver cannot inspect follower drawings, submissions or validity feedback.

Each round alternates one giver instruction and one follower reply. Follower JSON actions may replace its entire polyline with 2–128 finite local [x,y] points inside its own displayed axes, and may submit. Invalid drawing syntax preserves the last valid draft and provides private formatting feedback; no geometric correctness feedback is provided until the round closes. Empty submissions cannot end a round. The configurable max_turns bounds giver/follower exchanges, default six. Budget exhaustion scores the latest drawing as unsubmitted and unsuccessful. New-round setup clears drawings and submissions, but retains seat history. No provider/runtime failure substitutes a scripted agent or counts as successful play.

Landmarks are reference points rather than obstacles. The fixed physical target route is unchanged if a follower landmark is missing, duplicated or displaced. Shared anchors and relational instructions keep each example solvable. Grids exist for precise route entry; copying giver numbers cannot solve the follower's different frame. Cross-map coordinate conventions may legitimately be negotiated.

The ordered-frechet-v1 oracle maps follower local coordinates into the evaluator's world frame. It resamples both polylines at at most one world unit per sample, computes discrete Fréchet distance (preserving traversal order), endpoint maximum error, and submitted/target path-length ratio. Success requires explicit submission, Fréchet ≤3 world units, endpoints ≤2, and length ratio ≤1.15. These tolerances are immutable bank data. Per-round outcomes report success, route_error, endpoint_error, length_ratio and turns_used; episode success_rate is their mean. No threshold adjustment or oracle-informed fallback is used for live tests.

Public message events carry speaker/text/round. Observation events carry speaker/round/content/visibility=private with opaque asset digests. Each drawing event records the follower's exact committed route as a private image and an action/validation summary. Round_end records the same final drawing, submission status, and scored outcome with speaker=follower and visibility=private, so replay shows first-turn submissions as well as revisions and budget exhaustion. Round_end and final trace are evaluator evidence. Trace config pins the composite image-bank hash and all used image digests. Static images are banked; runtime draft overlays are content-addressed in config.asset_root and all enter final config.image_assets. These owner-visible trace artifacts are never automatically added to another seat's observation.

The root executable LangGraph is next_round → round child → score_round → next_round → finalize. The real child is begin_round → giver AgentStep → publish_instruction → follower AgentStep → record_drawing, looping only when unsubmitted with budget remaining. There is no descriptive workflow catalog or hidden agent call.

The shared runner owns opening/closing the attempt session; setup emits game_start before session.started, then play starts only after registration. Remote seats use staged /2 submit_action with deadline-scoped capability claims; action acknowledgment alone is not completion. Model execution, JSON parsing and accumulated conversation stay agent-side; validation, route commits, permissions, oracle and trace evidence stay environment-side.
