# Tangram Reference v1

A fixed director/matcher dyad completes 2–6 trials within one episode. The same
agent objects and agent-side private observation/output history persist across
trials. Six target permutations are frozen in one content-addressed item row.
Each figure comprises exactly the standard seven tangram pieces: two large
triangles, one medium triangle, two small triangles, one square and one
parallelogram. Geometry uses rigid reflections of boundary pieces; interiors do
not overlap. Black silhouettes omit internal piece boundaries and semantic names.

The director privately sees four numbered target slots. The matcher privately
sees the same figures in a differently ordered gallery with trial-local opaque
handles. The director has no gallery handles or matcher placements. The matcher
has no target image, target order, geometry, canonical IDs or oracle result.
Only natural-language messages and feedback on completed trials are shared.
Seat image observations are recorded separately with private visibility.
The reviewer trace also records the matcher's accepted board after each action
and its final board at submission or deadline. These images show the figures
chosen for each slot, with empty slots shown explicitly; they never replace the
board with the evaluator's answer. They carry private matcher visibility and
are absent from partner dialogue and agent observations. Exact generated bytes
and digest references are persisted alongside input images for replay.

Each exchange consists of director description followed by matcher response.
Actions contain `text`, optional complete `arrangement`, and optional `submit`.
Only matcher actions can change the board. An arrangement must use all four
current handles exactly once; invalid edits leave the board unchanged and yield
private syntax feedback. No intermediate correctness is reported. Submission
ends the trial; the exchange deadline scores the latest board. Missing placements
score zero for those slots. Feedback reveals only final accuracy and mismatched
slot numbers, after scoring. Successful submission requires exact slot order.
Communication may be wrong or unhelpful; there is no evaluator-informed fallback.

`num_rounds` and `max_exchanges` are resolved design settings. Inventory, piece
geometry, target orders, all 24 gallery layouts per trial and their assets are frozen item attributes.
The episode seed selects among those pinned layouts; resolved layout indices
are recorded in config. Handles remain opaque and unique to each trial. The item
oracle records only exact target orders, independent of dialogue budgets.
A two-round live pilot is a repeated-measures session, not two independent
observations. Compression claims require accuracy plus multiple repetitions;
this fixture only verifies the protocol and successful native image transport.

The executable LangGraph root is a round loop around a real trial child. The
child is description → publication → arrangement → validation/commit, followed
by clarification or score. Every model handoff is an explicit `AgentStep`.
The shared runner opens/closes the attempt-scoped session; the game enters
`session.started` with nonvisual role registration and executes play.

Local smoke agents classify their own raster pixels and communicate those
classifications as visible silhouette descriptions, without access to evaluator
order. This deterministic pixel-template policy is a scripted smoke fixture,
not a model response or evidence of learned reference conventions. Live and /2 model agents
preserve canonical multimodal history agent-side. Image capabilities are required
at environment and role admission. Every observation event retains digest/MIME
references, never raw image bytes. Packaged bank assets accompany the release.
